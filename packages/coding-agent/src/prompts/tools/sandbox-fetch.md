Fetch readable content from a public HTTP/HTTPS URL. HTML is converted locally to Markdown without scripts, styles or images; text and JSON remain text. The default method is GET. Use `raw: true` for complete decoded source text, API responses or custom processing; guest JavaScript `fetch()` always returns source text. Explicit methods, string headers and UTF-8 request bodies are supported. CONNECT and protocol tunnels are forbidden; no credentials are read from the host.

Destinations must resolve entirely to globally reachable addresses. Each redirect resolves and validates DNS again; connections can try alternate addresses only from that approved snapshot, without replaying HTTP requests. Localhost, private/reserved addresses, metadata, mapped IPv6, translation and tunnel ranges, URL credentials, and transport/proxy header overrides are forbidden. No ambient host proxies, Cookie jar, or account credentials are used. HTTPS verifies the original hostname and certificate. A browser User-Agent and Accept header are supplied unless explicitly overridden.

Limits: URL 8 KiB, method 64 characters, request headers 128 entries / 32 KiB, request body 1 MiB, response headers 32 KiB, at most 5 redirects, and 30 seconds overall including HTML conversion. Reader responses are bounded to 5 MiB on the wire and after decompression/charset decoding, then previewed at 100,000 characters. `raw: true` and guest JavaScript responses retain the 1 MiB bound. Cancellation closes owned DNS queries, sockets and response streams. Cross-origin redirects remove every explicit request header.

Returns JSON `{ "url": ..., "status": ..., "headers": ..., "body": ..., "format": "markdown" | "text", "truncated": ... }` containing the final URL, status, lowercase response headers and readable text. `truncated: true` means the preview omitted content; request a more specific URL or use raw/JavaScript processing. Raw mode omits `format` and `truncated` and returns the complete decoded source. Gzip, deflate and Brotli are decoded; response charset declarations are honored. HTTP error statuses remain readable responses; transport failures, forbidden destinations and limit violations are tool errors. A captcha, login, or JavaScript-only page is not the requested content: report that limitation rather than treating it as a successful search.

HEAD and HTTP no-content statuses return an empty `body` while preserving response headers. Their representation `Content-Length` and `Content-Encoding` do not trigger body limits or decompression.
